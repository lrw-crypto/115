# 草商探索趣：全站完成名次與前 15 名小獎品

目前 GitHub Pages 只提供靜態檔案。`assets/campus-rewards.js` 不會以 localStorage 冒充全站人數；只有收到計數服務回應後，才顯示第幾位與領獎畫面。尚未設定或連線失敗時保留八科完成紀錄、提供重新登記，並且不顯示任何領獎資格。

## 用校方 Google 帳號部署（免費；學生不需登入）

1. 用校方管理這次活動的 Google 帳號開啟 <https://script.google.com/>，新增專案。
2. 將本資料夾 `prize-counter.gs` 的全部內容貼進 `Code.gs`，儲存。
3. 在編輯器選取 `setupPrizeCounter`，執行一次並授權試算表存取。它會建立「草商探索趣－完成名次與領獎紀錄」；再次執行不會清空資料。
4. 按「部署」→「新增部署作業」→ 類型選「網頁應用程式」；執行身分選自己，誰可以存取選「所有人」。若校方帳號禁止公開部署，請由校方管理員提供允許的計數服務，前端不要放任何 Google 憑證。
5. 複製結尾為 `/exec` 的部署網址，填入 `assets/reward-config.js` 的 `window.CAMPUS_REWARD_API`。或將此公開網址提供給維護者代填。不要提供 Google 帳號密碼、token 或試算表私人分享網址。
6. 先用測試版／測試 Google 專案驗證，再開放正式活動。正式計數開始後，不要刪除或手動改寫名次、匿名編號、領獎編號欄。

校方可從建立的試算表核對領獎編號；確認發放實體獎品後，在最後一欄「已領取」手動註記，避免同一張截圖重複領取。程式不會自動判定獎品已實際領走。

## 計數規則

- 完成全部八科、取得八枚金幣後，客服自動登記；前 15 個**登記成功**的匿名瀏覽器紀錄可領獎。跨裝置同時完成，以後端取得鎖並寫入的順序為準。
- `LockService` 的全域鎖包住查重、編號與寫入，兩人同時登記不會取得相同名次；累積名次另以 Script Properties 保存最高值。
- 瀏覽器保存匿名 UUID。重試、重整、再次找客服或重玩第八科，都使用同一 UUID 取回同一名次。支援 Web Locks 的瀏覽器也會協調多分頁初次建立 UUID。
- 第 1～15 位顯示：恭喜、完成名次、截圖／校長室領獎說明與領獎編號；第 16 位起顯示：「恭喜完成！不好意思，獎品已發送完畢！」
- 後端只接收匿名 UUID 與八科完成代碼，不接收暱稱、性別、Discord 或其他個人資料。角色與暱稱仍只在此瀏覽器。
- 這是匿名活動紀錄，沒有身分認證；清除網站資料或換裝置會是另一個紀錄。八科完成狀態由靜態前端提交，也不能當作防作弊的身分證明。校方以領獎編號及實際領取紀錄核對，若要每位學生限領一次，需另提供校方認證方式。
- 舊版已集滿八枚者，再點客服也可登記；網站沒有過去所有人的全站紀錄，因此不會編造歷史完成人數。

## 回應格式與測試

POST：`Content-Type: text/plain;charset=UTF-8`，內容為 JSON：`{"clientId":"匿名UUID","completed":[八個科別代碼]}`。使用簡單跨來源請求，避免 Apps Script 不支援的自訂預檢。

成功：`{ok:true,rank:1,total:1,limit:15,eligible:true,completedAt:"ISO時間",receiptCode:"CS-001-XXXXXXXX"}`。重複 UUID 回傳原名次與領獎編號；16 位起 `eligible:false`。公開 GET 只回傳總人次與名額，不提供 UUID 或領獎編號。

`node tests/reward-counter.cjs` 驗證後端與鎖定／查重邏輯；`tests/browser-completion-rewards.cjs` 使用模擬 API 驗證前端。這些不會增加正式活動人數。實際 Google 網頁部署與瀏覽器跨來源連線，必須等 `/exec` 網址提供後另外驗證。
